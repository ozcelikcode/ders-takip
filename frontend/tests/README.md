# Frontend behavior tests

This folder holds screen-flow regressions that run screens with real React, Headless UI and TanStack Query components. The existing unit and component tests next to the code (`src/**/*.test.*`) keep running as well; a scenario is never duplicated in both places.

```bash
npm run test --workspace frontend -- tests/category-management.test.tsx tests/user-management.test.tsx tests/admin-settings.test.tsx
npm run typecheck --workspace frontend
npm run check
```

Vitest discovers files in both `src/` and `tests/`. `tests/` is covered by strict TypeScript and ESLint; a passing test run does not replace type checking or lint.

`category-management.test.tsx` covers permissions, telling errors from empty data, shared contract validation, partial updates, drafts during refetch, nested dialog focus and Escape, the pending-action lock, the target, errors and retry when moving a category, and a late response for a previous account. The API is a controlled mock in this test; a successful response is not evidence of real SQL or browser behaviour.

The real HTTP and SQLite regressions for permissions, atomicity, rollback and history preservation are in `backend/tests/catalog.test.cjs`, which runs only on databases created under `mkdtemp`. The live `.env`, user database and backups are never used as fixtures. When a manual browser check is needed, it uses separate ports and disposable data, and the processes and data are removed afterwards.

`user-management.test.tsx` covers server totals, paging and search across all records, errors and retry, protection of the signed-in account, asynchronous role, status and deletion confirmations (including the administrator password), correcting the last page, the create contract and its credential lifecycle, asking for the creator's password only when the new account is an administrator, and pending, duplicate, account-epoch and unmount boundaries. Real HTTP and SQLite paging, search and administrator create validation are in `backend/tests/user-management.test.cjs`; the shared rules are in `packages/contracts/tests/users.test.cjs`. Only disposable data is used.

`admin-settings.test.tsx` contains screen regressions against the real `settingsStore`: pristine and dirty refetch, partial and no-op saves, validation of hidden sections, read and write errors with retry, the lock for verified and unknown backups, asynchronous restore and reset with the administrator password, and account and unmount boundaries. The API is a controlled mock; the real snapshot, checksum, rollback and reset coverage is in the temporary-SQLite tests of `backend/tests/backups.test.cjs` and `backend/tests/admin-audit.test.cjs`. Races between private reads and writes are verified separately in `src/store/settingsStore.test.ts`.

`admin-overview.test.tsx` covers the administrator boundary, the global measured summary, the five statuses and types, and independent pending, error, retry and empty states. `session-surfaces.test.tsx` covers asynchronous server confirmation in TodaysPlans and CreateSessionModal, double-submit, epoch and unmount boundaries, drafts, versions and read retry after a 409, nested Escape and focus, clearing inactive records and historical titles and descriptions, routines, and accepting 1, 1.5 and 1440 minutes while rejecting 0 and 1441. The API is a controlled mock; these tests do not replace real HTTP and SQLite or browser tests.

`auth-forms.test.tsx` checks the shared registration and sign-in rules in the real React Hook Form forms. `contract-transport.test.ts` uses a real temporary HTTP server to verify that malformed responses are rejected, the DTO and id projection, and that a late password-change response cannot affect another account. Plan date, overlap, permission, detach, history and SQL rollback rules and the authentication and backup request boundaries are covered by the `mkdtemp` SQLite tests in `backend/tests/plans.test.cjs` and `request-contracts.test.cjs`; the real user database is never used.

`header-accessibility.test.tsx` covers pending, error, retry and empty states, malformed payloads, stale refetch, the last five entries and per-account read state, focus when the triggering action disappears, Popover Escape, mutual closing and outside targets, and a late read from a previous account. `src/components/planner/PlannerCalendar.test.tsx` covers the daily and weekly views: a single Tab stop with arrow, Home and End navigation, the time and duration fields, keeping an unsaved draft after a 409 and retrying with the latest version, invalid durations and cancel, source read retry, focus after the cell changes, neighbouring and cancelled card menus with source preservation, and the 23:59 gutter. `calendarGeometry.test.ts` covers two scales and hour boundaries, free lanes, stable ordering, immutable input and sub-minute positions. Real React and Headless UI are used and the API is a controlled mock. jsdom does no real pixel hit testing; real touch devices, full WCAG and production rendering are verified elsewhere.

Further files cover the welcome wizard (`onboarding`), interface language, vocabulary presets and custom words, region and notification settings, password reset and password change, search, statistics, goals and per-record goals, the weekly chart's screen-reader table, tags, account data export and import (`account-data`), the page switcher (`command-palette`) and the administrator activity log (`admin-audit`).
