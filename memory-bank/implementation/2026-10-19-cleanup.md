# Codebase cleanup — 19 October 2026

Source: a read-only knip and grep scan, followed by an implementation approved by the owner. Schema, migrations, persisted contracts and the real database did not change; design and product direction did not change.

## Done
- **Dead endpoints (phase 4, decision (b)):** `GET /categories/:id`, `/topics`, `/topics/:id` and `/users/:id` were removed with their routes, controllers, client calls and tests. The preferences test reads through `/auth/me` and the archive test counts in the database.
- **Dead code (phase 1):** `getSessionTextStyle`, five `calendarDates` helpers, unused pagination types, `authAPI.getMe`, dead classes in `index.css`, unnecessary exports and re-exports (`usePomodoro`, `useReadNotifications`, `studyTracking`, store types, `TokenResponse`) and the backend model `export default` lines were removed. The Tailwind `secondary`/`success`/`warning` palettes, `gray-750/850`, custom spacing and maxWidth, and the typography and aspect-ratio plugins were removed (`forms` stays). `frontend/.env.example` contains only `VITE_API_BASE_URL`. Developer comments in touched files were rewritten in English.
- **Configuration (phase 2):** `eslint-plugin-react-hooks` is a root devDependency; the browser-test server resolves `express` explicitly from the backend workspace; the placeholder `author` and the exam-specific description were removed; the README migration list (001–006), the Zod 3 mention and the status paragraph were corrected.
- **Type debt (phase 3):** 18 `any` were removed (`Express.Request.user: User`, Sequelize `WhereOptions`/`Includeable`, `unknown`, typed course and category responses, the Recharts label type). `@typescript-eslint/no-explicit-any` became `error`.

## Evidence
`npm run check` green (18 contracts + 141 backend + 200 frontend), `npm run test:e2e` 36/36. The production CSS output did not change (same content hash); no separate bundle size measurement was made. Remaining knip results: 3 CLI and Lighthouse entry files and `express` (a knip false positive because the browser tests resolve it with `require.resolve`).

## Not done
Major dependency upgrades, `npm audit` fixes, a LICENSE decision, adding knip as a permanent gate, `react-hooks/exhaustive-deps`. Course and category responses are typed but not validated at runtime (the A19 debt continued).

## Splitting large files (phase 5, same day)
Behaviour was kept, with the existing screen tests and 36 browser runs as evidence and pure logic extracted with unit tests:
- `CreateSessionModal.tsx` 1166→701: `sessionRequest.ts` (pure title, range, payload and label functions, 9 new tests), `SessionCategoryPicker`, `SessionDurationFields` (+`EndTimeSummary`), `PomodoroSettingsFields`, `SessionColorPicker`.
- `PlannerCalendar.tsx` 822→~625: `buildDaySegments`/`dayMinWidths`/`occupiedSlotKeys`/`slotNavigationTarget` moved to `calendarGeometry.ts` (4 new tests), plus `CalendarToolbar` and `SessionActionsMenu`. The drag and resize state machine was deliberately left in place.
- `services/api.ts` 569→391: the axios instances and interceptors moved to `services/httpClient.ts`; `api.ts` keeps the resource APIs and the default `api` export.
- `UserSettingsPage.tsx` 603→125: `ProfileTab`, `AppearanceTab`, `NotificationsTab`, `StudyTab`, `useProfileSettings` (form state is kept when switching tabs). Password and name validation moved from hand-written rules to the shared contract schemas (`changePasswordSchema`, `profilePatchSchema`); this is the only deliberate behaviour difference (the current password cannot be empty, shared error texts).
- `ProfilePage.tsx` 672→418: `ProfilePictureCard`, `AccountInfoCard`, `PasswordCard`, `profileForm.ts`.
- `CourseDetailPage.tsx` 647→396: `CourseHeader`, `TopicCard` and `courseTopics.ts` (sort, filter and statistics, 3 new tests) under `pages/course/`.
Evidence: `npm run check` green (18 contracts + 141 backend + 216 frontend), `npm run test:e2e` 36/36 (one run showed an axe color-contrast finding on the profile page; it appeared to be a timing issue from scanning during the fade-in animation, the single test passed 3/3 and the full matrix passed again — flake risk open).
Open observation: the Profile and Settings pages offered the same profile and password functions in separate interfaces; merging them is a product decision and was not done. Notification switches (email, push, reminders) were stored as preferences but had no delivery.

## R1 — audience-neutral language and fields (same day, after the product direction decision)
`roleLabel` (`lib/roleLabels.ts`) is the single source for six repeated administrator/student labels; the display name became the neutral "user" label while the persisted role value `student` did not change. The `studyField` contract was widened from a fixed exam-code enum to free text `string().trim().max(60).nullable()` (old values stay valid, no migration, 1 new contracts test); the profile field became a free-text "focus area". The second `Topic` type in `types/planner.ts` (`category: 'TYT' | 'AYT'`) was removed in favour of `CatalogTopic`. Administrator texts (reset and backups) moved to the neutral "user" wording; the `education` keyword was removed. Evidence: check green, browser test result recorded in progress.
