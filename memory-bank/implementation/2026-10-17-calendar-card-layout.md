# A22 — Short calendar card layout

The minimum hit height of short sessions could cover neighbouring cards across hour boundaries. The shared `calendarGeometry` now builds connected overlap groups from the real pixel start and a visual height of at least 28 px; it reuses free columns and sorts stably by ID on equal starts. The UTC start, end, duration, status and note values of the records are never changed. Cancelled and other visible cards take part in the same layout. Every interaction column is at least 160 px; empty weekly days stay 104 px. The header and the hours use the same column template, and busy days scroll horizontally. A 36 px gap at the end of the day protects the last-minute card and its focus ring.

Card title and icon targets are at least 24 px and fit in the 28 px shell; under 68 px the card is a compact row. The resize handle that covered the target on short cards (under 36 px) was removed; the existing "Change time and duration" alternative is kept. Large cards keep pointer resize. Seconds and milliseconds are kept at the calendar start; no record's time is shifted. Daily and weekly views use the same engine; DOM order is the visible start/ID order.

Verification: **18 contracts + 142 backend + 200 frontend = 360 tests**, nothing skipped; `npm run check` naming, strict, lint and production build passed. After the last visual spacing and ordering change, frontend strict mode, root lint, 200 tests and the production build passed again. There are 4 new geometry regressions and 4 component regressions across the daily and weekly views. A separate temporary production fixture checked 1-minute neighbouring cards and a cancelled record, the keyboard menu, Escape and focus, and the 23:59 target. Every column of the five sessions matched the earlier snapshot; no interval was produced, integrity and foreign keys were clean. The real user database, schema and dependencies did not change. The fixture tab, processes and temporary data were cleaned up; the root dev server on 3000 / API 5002 was kept.

A22 was not closed as a whole: real touch devices, the DST fold, full WCAG and screen readers, Lighthouse and automated real-browser tests were open. The A04 and dependency backlog continued.
